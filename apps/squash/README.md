# 玻璃禁區・壁球

一款從後方玻璃觀看、強調同場搶位與擊球品質的單人壁球遊戲。它沿用網球專案已驗證的角色動畫品質，但不是換皮模式：球場座標、鏡頭投影、碰牆物理、回合規則與 AI 都為壁球重新設計。

## 遊戲內容

- 11 分制 point-a-rally，10:10 後必須領先兩分。
- WASD 在同一座球場內移動，Shift 消耗氣力閃身。
- J 平抽、K 小球、L 側牆球、Space 高吊；未發球時 Space 為平抽發球。
- 左右方向鍵調整前牆瞄準點。
- 球必須先合法碰到前牆，最多落地一次；打中 tin、出界或第二次落地即失分。
- 飛行中的球會在地板顯示即時預測落點；經過側牆或後玻璃反彈後會持續重算。
- AI 會預測攔截點、回到 T 區，並根據玩家站位選擇平抽、小球、高吊或側牆球。

## 為什麼鏡頭不同

壁球的資訊不是「球越過球網」，而是「球打到牆的哪裡、經過哪一面側牆、從哪個角落彈回來」。因此採用後玻璃視角：

- 前牆固定在畫面上方，直接成為瞄準介面。
- 地板以梯形透視延伸，後場較寬、前場較窄。
- 人物和球會依深度縮放，讓前後距離可讀。
- 球的畫面高度同時呈現真實高度，牆面撞點會產生光圈。
- 半透明側牆、後玻璃與 T 區標記讓同場搶位關係清楚。

## 動態場館

球場不是由純色幾何圖形構成，而是多張圖像分層合成：

- 場外全景：左右看台、上層觀眾、攝影區、鋼構與場館燈。
- 前牆：複合牆板、板縫、球痕、磨損與中心光差。
- 地板：楓木板、鞋痕、刮痕與冷色場館反光。
- 左右牆與後牆：獨立玻璃污痕、折射、邊緣高光和燈具倒影。
- 動態觀眾：四組各六幀的待機、拍手、歡呼與攝影動作。

觀眾平時以不同相位循環，避免整排同步。得分後會切換成較強烈的歡呼／攝影動作。玻璃約每 5.2 秒產生一次邊緣高光掃亮，得分時額外連續呼吸；場館同時有緩慢移動的燈束與錯開的攝影閃光。

## 擊球品質與戰術鏈

每次接觸會即時計算 `quality`。球離人物越遠、球越高、閃身尾段才勉強救到，或氣力過低，品質就越差。

低品質不是只有 HUD 數字變低：它會放大方向散布、降低球速與深度，並讓球坐到中場。這會形成完整戰術鏈：

1. 用落點或側牆球把對手調離 T 區。
2. 對手伸展或閃身尾段勉強救球。
3. 回球變淺、變慢、方向不穩。
4. 玩家提早站上 T 區，以平抽或小球終結。

## 角色動畫

專用後視角角色動畫共 60 幀：

- 12 幀：面向前牆的待機、墊步與偶爾向左注視。
- 12 幀：面向前牆的前進、橫移、回位與後退。
- 12 幀：後視角正手平抽。
- 12 幀：後視角反手穿越。
- 12 幀：朝前角衝刺並失衡伸拍的低牆救球。

角色的基準姿勢永遠背對後玻璃、面向前牆，不再依水平移動把整個人物左右翻面。正反拍只在接觸前後轉動肩髖；失衡救球才露出少量側臉。人物情緒由眼神、眉眼、嘴型、軀幹扭轉和重心演出，不使用頭頂表情符號。擊球在第 7 幀觸發物理事件，讓拍面、球聲和球的離手時點一致。`sprite-gallery.html` 可循環檢查五套後視角動作。

## 製作流程

1. 以標準壁球場尺寸建立世界座標和合法線高度。
2. 建立後玻璃透視投影，將世界座標、球高與人物深度映射到畫面。
3. 實作前牆、側牆、後玻璃、地板碰撞與回合判定。
4. 加入品質模型、散布、強制淺球與 AI T 區決策。
5. 以既有角色身份生成後視角壁球動作，移除色鍵背景，再逐格正規化到共同腳底基線。
6. 分別生成場館、牆面、地板、玻璃和觀眾動畫，利用透視多邊形遮罩合成。
7. 將動作接觸幀與物理擊球同步，補上軌跡、落點、撞牆光圈、音效與 HUD。
8. 進行 TypeScript/Vite 全專案編譯與瀏覽器 round-trip：實際發球、AI 回擊、落地、判分、觀眾反應並看到比分更新。

## 開發

```bash
npm run dev -w squash
npm run build -w squash
```

主遊戲預設在 `http://localhost:5175/`，動作驗收室在 `http://localhost:5175/sprite-gallery.html`。
